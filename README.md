# entropic

How much of your writing did a language model see coming? Paste text in and
see which passages a model predicted easily (red) and which it could not have
guessed (green), set against several hundred reference texts by people and by
models.

Live at https://ishanjmukherjee.github.io/entropic/

## How it works

The page sends your text to a language model and reads back the
log-probability the model assigned to each token given everything before it.
Each token has a surprisal, `-log2(p)`: 0 bits means the model was certain,
10 bits means a one-in-a-thousand guess. Single tokens are noisy, so by
default the page shades passages of one to three sentences by their mean
surprisal; hovering a passage shows its mean and the tokens that drove it.
Ticking "per token" shades every token on its own, and hovering one shows
what the model expected instead. The summary reports mean surprisal in bits
per token and how often your token was the model's first guess.

Red means predictable and green means surprising. The colour scale for
passages is not fixed: it comes from the reference texts for the kind of
writing being compared (essays, fiction, poems, songs, plays or code). Full
red is where the most predictable tenth of model-written passages sit, full
green is where the most surprising tenth of passages by people sit, and the
neutral point is the value that best separates the two.

## Reference texts

A score means little alone, so the page shows where a text lands among
reference texts ("where texts land"): writing by people that the scoring model
cannot have read (published from August 2026 on), older writing by people
sorted by how well known it is, and writing by models from several families
given the same prompts. Each text is measured on its opening 3,000
characters, and the marker for a pasted text uses its opening too. A pasted
text is assigned a kind by a rough guess, which the tabs overrule.

"The shelf" lists texts scored ahead of time. Opening one shows its heatmap
without calling the scoring service. Texts by people on the shelf are
public-domain works and pieces published on the open web without a paywall;
only the scored opening is reproduced, with a link to the source.

The study behind this is in [baselines/](baselines/): the plan written before
scoring ([PLAN.md](baselines/PLAN.md)), the generated texts and their prompts,
and per-document results. It is unfinished; [AGENTS.md](AGENTS.md) lists what
remains. `baselines/build_site.mjs` turns the results into `data/`.

The text is the entire prompt: no instructions, no chat formatting. The model
is `moonshotai/Kimi-K3` served by [Featherless](https://featherless.ai), with
`moonshotai/Kimi-K2.6` as the fallback when it is busy. These are instruction-tuned models used as plain next-token
predictors. That choice, and the choice of no hidden prompt, came out of a
preregistered evaluation on recent human writing; see
[eval/RESULTS.md](eval/RESULTS.md). A pretrained model would be the natural
fit, but the only one callable this way (`google/gemma-4-26B-A4B`) is rarely
available, and a direct comparison against it is still owed.

Two Featherless behaviours shape the request in `main.js`:

- Log-probabilities are only returned on streamed responses (`stream: true`);
  the non-streamed response has `logprobs: null`.
- Only some model backends honour `echo: true`, which returns log-probabilities
  for the prompt itself. With it, a whole essay is scored in one request.

Long texts are split into windows of about 24,000 characters, each sent with
4,000 characters of preceding context whose scores are discarded.

## Files

- `index.html`, `style.css`, `main.js`, `score.js`: the whole app; there is no
  build step. `score.js` holds the pure helpers: token
  alignment, windowing, sentence splitting and passage grouping.
- `data/`: generated by `baselines/build_site.mjs`. `baselines.js` holds the
  reference distributions and colour scales, `library.js` the shelf listing,
  and `library/` one file of scored tokens per shelf text. Do not edit by hand.
- `baselines/`: the reference-text study. `library.json` is the list of texts
  on the shelf.
- `worker/`: the scoring proxy.
- `eval/`: the preregistration, corpus builder, runner and results for the
  model and prompt choice.

## Running locally

```sh
python3 -m http.server 8000
```

Then open http://localhost:8000. The proxy accepts requests from that origin,
so scoring works there; the shelf works from any origin.

## The scoring proxy

The page has no key of its own. Shared scoring goes through a small
Cloudflare Worker (`worker/`) that holds the Featherless key as a secret and
forwards only the one request the page needs: a known model, one output token,
at most 30,000 characters. It answers browsers only from this site's origin,
limits each visitor to 20 requests a minute, and stops for the day after a
character budget set in `worker/wrangler.toml`. A script can fake the origin,
so the limits are what bound the cost. Texts on the shared budget are capped at
60,000 characters. Visitors can supply their own key under "settings and
privacy"; it is stored only in their browser and used to call Featherless
directly.

To deploy the Worker: `cd worker`, `npx wrangler deploy`, then
`npx wrangler secret put FEATHERLESS_KEY`.

An earlier version shipped a key in `main.js`. That key has been revoked.
